# Threat Model: Van Suraksha (Forest Fire Monitoring Dashboard)

## Executive Summary
The Van Suraksha dashboard is a critical infrastructure tool for monitoring and responding to forest fires in the Guna Division. The primary security risks involve the integrity of fire alerts (spoofing or suppressing alerts) and the availability of the system during active fire events. Unauthorized access to the automated tactical dispatch engine could lead to dangerous ground crew directives.

## Scope and Assumptions
### In-Scope Paths
- `src/analysis/`: Core logic for fire detection and tactical dispatch.
- `dashboard/`: Streamlit interface and 3D simulation.
- `data_lake/`: Persistence layer for satellite and weather data.
- `scripts/`: Data ingestion pipelines.

### Assumptions
- **Internal Use:** The system is intended for internal use by Forest Department officials and is not exposed to the public internet without a VPN or proxy.
- **Human-in-the-Loop:** Tactical dispatch orders are reviewed by an operator before being communicated to ground crews.
- **Secrets Management:** API keys (NASA, OpenAI, Pika) are stored in `.env` and are not committed to version control.
- **Physical Security:** The server hosting the dashboard is in a secured government facility.

## System Model
### Primary Components
- **Ingestion Pipelines:** Fetches NRT (Near Real-Time) data from NASA FIRMS and GFS.
- **Analysis Engine:** Computes FWI and fire intensity metrics.
- **AI Signal Corps:** Generates bilingual tactical orders.
- **3D Digital Twin:** Visualizes physics-based fire spread simulations.

### Data Flows and Trust Boundaries
- **Internet → Ingestion Scripts:** External APIs provide untrusted data.
- **Dashboard → User:** Interaction boundary (requires authentication).
- **Analysis Engine → AI Signal Corps:** Critical decision logic boundary.
- **Sim Server (Port 8001) → 3D Twin:** Simulation data stream.

## Attacker Model
### Capabilities
- **Internal Insider:** Access to the local network; can view the dashboard.
- **Remote Script Kiddie:** Scans for open ports (e.g., 8501 or 8001) on public IPs.
- **Sophisticated Adversary:** Goal is to disrupt government operations or cause public panic.

### Non-Capabilities
- Compromise of NASA or IBM/NASA Prithvi model infrastructure.

## Top Abuse Paths
1. **Alert Suppression:** Attacker blocks ingestion of NASA FIRMS data during a deliberate arson event.
2. **Tactical Misdirection:** Attacker modifies the prompt or logic in `src/analysis/ai_dispatcher.py` to send crews into unsafe zones.
3. **Simulation Poisoning:** Attacker sends malformed data to the 3D Twin to hide the actual direction of fire spread.
